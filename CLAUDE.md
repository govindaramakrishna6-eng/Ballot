## 1. What we are building

A voting DApp on Ethereum (Sepolia testnet) with four core features:
1. Anyone can create a poll (title, optional description, 2–10 options, deadline).
2. Users connect an Ethereum wallet (MetaMask and others via RainbowKit).
3. A connected wallet can cast exactly one vote per poll before the deadline.
4. Anyone, even without a wallet, can view live and final results.

The product idea that makes it ours: **every vote is provable, and the UI shows the proof.**
After voting, the user gets a "ballot receipt" (tx hash, block number, timestamp, network,
Etherscan link) styled like a printed paper receipt. Verifiability is the hero, not decoration.

## 4. Smart contract spec — `VotingDApp.sol`

### Data
- `struct Poll { uint256 id; address creator; string title; string description; string[] options;
  uint256[] voteCounts; uint64 createdAt; uint64 endTime; uint256 totalVotes; bool cancelled; }`
- Poll ids start at **1** (so 0 can never be a valid poll; avoids default-value bugs).
- `uint256 public pollCount;`
- `mapping(uint256 => mapping(address => uint256)) votedOption;`
  stores optionIndex + 1, so 0 means "has not voted" (mapping default value).

### Limits (public constants, mirrored exactly in the frontend)
- Title: 1–120 bytes. Description: 0–500 bytes. Each option: 1–60 bytes.
- Options: 2–10. No duplicate options (exact byte comparison via keccak256).
- Duration: endTime must be at least 5 minutes and at most 30 days after block.timestamp.
- Note: limits are in BYTES, not characters. Tamil, emoji and other non-ASCII text use more
  bytes per character. The frontend must count with `new TextEncoder().encode(s).length`.

### Functions
- `createPoll(string title, string description, string[] options, uint64 endTime) returns (uint256 pollId)`
- `vote(uint256 pollId, uint256 optionIndex)`
- `cancelPoll(uint256 pollId)` — only the creator, only while open, only if totalVotes == 0
  (a creator must not be able to erase a poll that is going against them).
- `getPoll(uint256 pollId) view returns (Poll)`
- `getPollsPage(uint256 startId, uint256 limit) view returns (Poll[])` — ids startId..startId+limit-1,
  clipped to pollCount; limit capped at 50; returns empty array if startId > pollCount.
  (Unbounded arrays in view calls eventually hit RPC limits, so we paginate from day one.)
- `getVotedOption(uint256 pollId, address voter) view returns (uint256)` — 0 = not voted, else index+1.
- No `receive`/`fallback`, nothing payable: the contract must reject plain ETH transfers.
- There are no external calls, so no reentrancy surface; state that in a comment.

### Rules enforced in `vote` (custom errors, not require strings)
1. Poll exists (1 ≤ pollId ≤ pollCount) → else `PollNotFound(pollId)`
2. Not cancelled → else `PollIsCancelled(pollId)`
3. `block.timestamp < endTime` → else `PollEnded(pollId)` (voting at exactly endTime is rejected)
4. `optionIndex < options.length` → else `InvalidOption(pollId, optionIndex)`
5. Sender has not voted → else `AlreadyVoted(pollId, msg.sender)`
Voter identity is always `msg.sender`, never a parameter.

Other errors: `InvalidTitle`, `InvalidDescription`, `InvalidOptionCount`, `EmptyOption(index)`,
`OptionTooLong(index)`, `DuplicateOption(indexA, indexB)`, `InvalidEndTime`, `NotCreator`, `PollHasVotes`.

### Events
- `PollCreated(uint256 indexed pollId, address indexed creator, uint64 endTime)`
- `Voted(uint256 indexed pollId, address indexed voter, uint256 optionIndex)`
- `PollCancelled(uint256 indexed pollId)`

### Known, accepted limitations (go in README, not "fixed")
- One wallet = one vote, not one person = one vote (Sybil). Anyone can make many wallets.
- Votes are public on-chain: anyone can see which address chose what.
- Anyone can create polls; spam is limited only by gas cost.
- block.timestamp can drift by a few seconds; fine for polls measured in minutes/days.
- Contract is immutable after deploy; fixing a bug means a new deployment and address.

## 5. Contract test checklist (all must exist and pass)

Creation: valid poll; pollCount increments; ids start at 1; event args correct; exactly 2 and
exactly 10 options OK; 1 and 11 options revert; empty title, title of 121 bytes, empty option,
61-byte option, duplicate options, description of 501 bytes all revert with the right error;
endTime in the past, < 5 min ahead, > 30 days ahead revert; exact boundaries (5 min, 30 days) OK;
a multi-byte (Tamil/emoji) string that is under the char count but over the byte limit reverts.

Voting: valid vote increments the right count and totalVotes and emits Voted; getVotedOption
returns index+1; two different voters both counted; same voter twice reverts AlreadyVoted;
voting for option index == length reverts; pollId 0 and pollId > pollCount revert PollNotFound;
voting 1 second before endTime works; voting at exactly endTime and after reverts PollEnded
(use Hardhat time helpers); creator can vote in their own poll.

Cancel: creator cancels poll with 0 votes; non-creator reverts NotCreator; cancel after a vote
reverts PollHasVotes; cancel after end reverts; vote on cancelled poll reverts PollIsCancelled.

Reads: getPollsPage with startId beyond count returns empty; partial last page clipped;
limit above 50 capped. Sending ETH to the contract reverts.

Also print a gas report for createPoll (2 and 10 options) and vote.

## 6. Frontend spec

### Pages
- `/` — poll list. Tabs/filters: Open, Closed, Mine (created by me). Sort newest first.
  Each card: title, status pill, countdown or "ended <date>", total votes, leading option, my-vote mark.
- `/create` — create poll form (wallet required to submit, not to view).
- `/poll/:id` — poll detail: question, description, options, vote action, live results, receipt.
- `/me` — polls I voted in (via batched getVotedOption calls over loaded polls). Phase 6.
- Any unknown route or nonexistent poll id → a proper "not found" state, not a crash.

### Reading data
- The app must work read-only with no wallet installed, using a public RPC transport
  (`VITE_SEPOLIA_RPC_URL`). Remind me in the README to restrict that key to my domain,
  because anything in a Vite env var is public.
- Contract address, ABI and deploy block come from `frontend/src/contract/deployments.json`,
  written by the deploy script, keyed by chainId. If the current chain has no deployment, say so.
- Missing env vars → a clear startup error screen naming the missing variable.
- Poll status must use chain time, not only the user's clock: read the latest block timestamp,
  compute an offset, and drive countdowns from local clock + offset. When a countdown hits zero
  the poll flips to Closed without a page refresh.
- Times are shown in the user's local timezone with the zone label (e.g. IST).

### Writing data (every write goes through one shared hook/component)
Flow: simulate first (useSimulateContract) → wallet prompt → pending → confirmed / failed.
- Simulation catches reverts BEFORE the wallet pops up; decode custom errors with viem and map
  each one to a human sentence (e.g. AlreadyVoted → "This wallet has already voted in this poll.").
  Never show raw error dumps; put technical details behind a "Details" toggle.
- User rejected in wallet → neutral message ("Vote not sent."), not a red error.
- Insufficient funds for gas → explain and link a Sepolia faucet.
- Pending → show tx hash + Etherscan link immediately. Store pending tx hashes in localStorage
  so a page refresh resumes watching instead of losing the vote.
- Buttons disabled while a tx for that action is in flight (no double submits).
- Tx reverted after mining → show the decoded reason.
- After confirmation, refetch from chain (do not just increment locally, to avoid double counts).
- Status changes are announced via an `aria-live` region.

### Wallet edge cases
- No wallet extension → RainbowKit's install options; browsing still works.
- Wrong network → banner with "Switch to Sepolia" button; all write buttons disabled with reason.
- Account switched while on a poll → re-check getVotedOption for the new account immediately.
- Wallet disconnected mid-flow → return to read-only state gracefully.
- Mobile → MetaMask's in-app browser works (injected); WalletConnect works when its project id is set.

### Live updates
- Watch `Voted` and `PollCreated` events for visible polls; on event, refetch that poll.
  Dedupe by tx hash + log index. If the event watcher fails, fall back to polling every ~12s.

### Results display
- Show both count and percentage. 0 total votes → "No votes yet", never NaN or divide by zero.
- Percentages may not sum to exactly 100 due to rounding; counts are the truth.
- Ties → "Tied" label; a "Winner" label appears only when the poll is closed and there is no tie.
- Cancelled polls show a Cancelled state and no results bars.

### Create form validation (mirrors section 4 exactly)
- Live byte counters on title, description and each option.
- Add/remove option rows (min 2, max 10). Trim whitespace. Exact duplicates blocked;
  case-insensitive near-duplicates ("Yes"/"yes") get a warning but are allowed.
- Deadline picker limited to 5 minutes–30 days from now, plus quick presets (1h, 1d, 7d).
- Show a review step before signing: "This is permanent and can't be edited."
- After confirmation, read the new poll id from the PollCreated event and navigate to it.

### Content safety
- Render all poll text as plain text, preserve line breaks, never auto-link URLs.
- Truncate long titles/addresses visually (with full value on hover/title attribute), never break layout.
- Addresses shown as 0x1234…abcd with copy button; show ENS name if available (Phase 6).

### States every screen must have
Loading (skeletons, not spinners everywhere), empty (an invitation: "Create the first poll"),
error with retry, and RPC-down state.

## 7. Design direction — "civic paper", NOT generic Web3

Read `/design-refs` before any UI work and tell me what you took from each screenshot.
Take patterns, never copy a brand's logo, colours or name.

The feel: a modern polling station. Paper, ink, stamps, receipts. Calm, trustworthy, legible.
- Palette: warm off-white paper background, near-black ink text, one accent colour used
  sparingly for "stamped" moments (a deep ballot green or vermilion — propose one).
  Proper dark mode: dark paper, light ink, same accent.
- Type: a characterful display serif for poll titles (e.g. Fraunces or Instrument Serif),
  a clean sans for UI (e.g. IBM Plex Sans), a monospace for hashes/addresses/numbers
  (e.g. IBM Plex Mono). Tabular numerals for vote counts.
- Motifs: perforated/dashed edges on the ballot receipt, a subtle stamp animation when a vote
  confirms, results as thick ink bars, status as small printed labels.
- Motion: short and purposeful; respect `prefers-reduced-motion`.

Banned: purple-to-blue gradients, neon glows, glassmorphism, 3D coins/blobs, floating particles,
"Revolutionizing democracy" hero copy, emoji as icons, walls of cards with identical shadows.

Accessibility: keyboard reachable everything, visible focus, WCAG AA contrast in both themes,
results understandable without colour.

In Phase 5, build two variations of this direction as static poll-page screens, screenshot both
in light and dark, critique them against this section and the banned list, pick the stronger one,
log why in BUILD_LOG.md, and apply it.
